# Airport Navigator web app

Vue 3 + TypeScript + Vite front end for Airport Navigator. It provides the airport selector, journey
entry, live flight review, OpenStreetMap map, A* routing, live navigation, layover assistant,
dark/light theme and optional account screens for BLR, DEL, BOM, HYD, MAA and CCU.

> OpenStreetMap data is not field-verified. Some entrance/level/connector segments are inferred and
> drawn dashed. Indoor GPS can be inaccurate. Airport signs and staff take precedence.

## Run

From the repository root:

```bash
npm install
npm --prefix apps/web install
npm run dev:server   # API on :8787
npm run dev:web      # Vite on :5173, proxies /api
```

The web app can also run alone for the map/manual/demo flows, but live flights and accounts need the
API. The API is same-origin at `/api`; in development Vite proxies it to port 8787.

## Checks

```bash
npm run typecheck
npm run test
npm run build
```

## Main modules

- `src/modules/airport-directory/` — lazy airport registry, catalogue, validation, POI search and gate fallback.
- `src/modules/navigation/` — A*, costs, route validation, directions, live progress, geo helpers.
- `src/modules/flights/` — live board adapter, manual and demo providers, validation, lookup service.
- `src/modules/journeys/` — connection assessment, transfer scenarios and facility recommendations.
- `src/modules/live/` — queue, weather and aircraft-position clients.
- `src/composables/usePushNotifications.ts` — Web Push subscription and watch management.
- `src/components/MapCanvas.vue` — MapLibre map, OpenFreeMap tiles, markers, route/shuttle overlays, user dot.
- `src/views/` — home, flight review, map, journey assistant, account and data/privacy screens.
- `src/stores/` — selected-airport dataset, journey persistence and optional account session.
- `src/composables/useTheme.ts` — persisted light/dark theme and system preference.

## Data

`src/data/airports/blr/` is generated by `scripts/build-osm-data.mjs`; the other airport folders use
`scripts/build-airport-datasets.mjs`. Each dataset contains terminal polygons, floors, POIs and graph
nodes/edges with provenance metadata. BLR also contains mapped rooms and the T1↔T2 shuttle. See
[`docs/osm-attribution.md`](docs/osm-attribution.md) and
[`docs/data-sources.md`](docs/data-sources.md).

## Known limitations

- OSM indoor coverage is partial; BLR T1 walkways and some T2 levels use inferred connectors.
- DEL, BOM, HYD, MAA and CCU use schematic terminal-level connectors, not mapped indoor corridors.
- No field-verified accessibility audit.
- Security/immigration boundaries are not directional graph rules; terminal-change routes warn
  explicitly.
- The BLR board covers the current airport day; other airports and dates need the optional AeroDataBox provider or manual entry.
- The basemap uses OpenFreeMap vector tiles; keep OpenFreeMap/OpenMapTiles/OSM attribution visible.
- Web Push delivery is best-effort and needs a stable VAPID keypair in production.
- ADS-B aircraft position may be unavailable indoors or when OpenSky is unreachable.
